Refill Readiness: keeping GLP-1 patients on track between refills

A feature idea for Bask's platform that helps brands make sure patients get their next refill before they run out.

By Yara Eissa · Product Owner applicant · Portfolio

Why I picked this problem: I read Bask's article "What a GLP-1 Telehealth Platform Actually Needs to Get Right in 2026". It says providers need to see refills that need review before they go out. I wanted to show how I'd turn that into a feature.

1 · The problem

Patients run out before their next refill arrives

GLP-1 treatment works in dose steps, and moving up a step needs a provider's approval. Today the refill process often starts only when the patient is already out of medication. The patient misses doses, contacts support, gets frustrated and may cancel.

30%of GLP-1 patients stop in month 1
58%stop within 12 weeks
$30+cost of one support ticket handled by a person
Providers need visibility into "patients approaching a refill that requires clinical review before it goes out."Bask Health blog, 2026

2 · Who it affects

Three groups feel it

Brands

Bask's customers. They lose patients and pay for repeat support tickets.

Patients

They miss doses and don't know where their order is.

Providers

They review refills in a flat list with no sense of which ones are urgent.

3 · The solution

Start the refill 10 days before the patient runs out

Bask already knows when each order ships and how many days of supply it holds. Refill Readiness uses that to start the next refill early.

Early check-in

Patients get a short check-in (dose, side effects, weight) 10 days before they run out, built with Bask's questionnaire builder.

Refills-due list

Providers see refills sorted by run-out date. Dose changes are flagged. Same-dose refills can be approved in one click.

Order tracker

Patients see each step in their portal, so they don't need to ask support.

6 · How it works

The core logic is small

A daily job finds patients whose check-in date has arrived. Names are my own, since I haven't seen Bask's code.

const DAY = 86_400_000;

function checkInDate(order, leadDays = 10) {
  const runOut = order.shippedAt.getTime() + order.supplyDays * DAY;
  return new Date(runOut - leadDays * DAY);
}

// Dose changes always go to a provider
function needsReview(order, sideEffects) {
  return order.nextDose !== order.currentDose || sideEffects;
}

7 · Success & risks

How we'd know it works, and what to watch

Measure

  • Refills delivered before run-out
  • Patients still active at 3 months (+5 pts, assumption)
  • "Where is my order?" tickets (−30%, assumption)

Watch

  • Safety: dose changes always need a provider
  • Privacy: no health details in SMS or email
  • Workload: provider review time shouldn't go up
